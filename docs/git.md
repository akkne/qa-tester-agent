# Работа с Git

Исходная ветка для демонстрации — `main`. Автоматически публикуемые ветки имеют формат `qa/<short-sha>-<run-id>` и создаются строго от проверяемого `headSha`. GitHub Actions слушает только исходную ветку и игнорирует push, состоящий исключительно из файлов отчёта. Точный диапазон берётся из `baseSha..headSha`; текущий указатель ветки во время обработки не используется.

Коммиты разработчика и агента используют Conventional Commits: `feat(scope): …`, `fix(scope): …`, `test(scope): …`, `chore(scope): …`. Один коммит содержит одну законченную логическую единицу. В теле кратко записываются сделанное и причина. `Co-Authored-By` и упоминания ИИ не добавляются.

Перед каждым коммитом выполняются все доступные проверки проекта: форматирование, линтер/анализаторы, компиляция и правила зависимостей, полный набор тестов. Нельзя коммитить секреты и заполненные `.env`; `.gitignore` игнорирует локальные файлы окружений, а `*.example` остаются шаблонами. QA-ветка допускает только тесты и `revision/`.

Локальный репозиторий инициализирован на `main`; GitHub remote пока не задан. Для завершения М1 нужно добавить remote, проверить доступ к нему и работу self-hosted runner. Адрес remote и права push не задаются в архитектурной документации, так как они зависят от конкретного приватного репозитория. Для первого автоматического запуска указывается базовый commit SHA.
