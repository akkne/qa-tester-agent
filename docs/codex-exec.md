# LLM через Codex CLI

`QaAgent.Application` продолжает обращаться к порту `ILlmClient`. Реализация `CodexExecLlmClient` вызывает `ICodexExecRunner`, который для каждого запроса создаёт отдельный процесс `codex exec`. HTTP-клиент и OpenAI-совместимый endpoint удалены из пути M2. Формат CLI соответствует [официальному примеру OpenAI с `--output-schema` и `--output-last-message`](https://developers.openai.com/cookbook/examples/codex/build_iterative_repair_loops_with_codex); учёт токенов берётся из `turn.completed` JSONL, как описано в [руководстве по автоматическим проверкам](https://developers.openai.com/blog/eval-skills).

## Наблюдение за агентом

Страница `/runs/{runId}` показывает ленту работы, обновляемую каждые три секунды. Она объединяет этапы worker и сообщения всех вызовов Codex для данного запуска. События `codex exec --json` читаются и сохраняются по мере их появления, поэтому сообщения видны до завершения процесса. Лента также доступна как `GET /runs/{runId}/activity?after=<номер>` и защищена той же HTTP Basic авторизацией, что и страница результата. Файлы ленты хранятся отдельно от публикуемых артефактов в `Agent__ActivityRoot` (по умолчанию `activity/`).

Это лента запуска QA-агента, а не одна сессия в приложении Codex: план, анализ, генерация и исправления выполняются в отдельных `--ephemeral` процессах. Сохраняются этапы и завершённые сообщения агента. Входные prompt, сырой stderr, команды и внутренние рассуждения не сохраняются.

## Установка и авторизация

Установите Codex CLI на машине хоста, выполните `codex login` от имени пользователя, под которым работает `QaAgent.Host`, и проверьте `codex login status`. В этой конфигурации используется вход ChatGPT; `Llm__ApiKey` не требуется. Убедитесь, что исполняемый файл доступен службе через `PATH`, либо задайте абсолютный путь `Llm__CodexExecutable`. Для выбора модели можно задать `Llm__Model`; пустое значение оставляет выбор за CLI. Локальный smoke-вызов с реальным CLI и текущим ChatGPT login вернул схему `{"ok":true}` и событие `turn.completed` с токенами.

`Llm__TimeoutSeconds` ограничивает каждый вызов (по умолчанию 600 секунд). Общий лимит запуска задаёт `Agent__RunTimeoutMinutes`; `Agent__StageTimeoutMinutes` пока ограничивает Git-этап. М2 делает до пяти вызовов: план, находки, генерация и до двух исправлений тестов. Эти лимиты надо согласовать для длинного прогона; отмена верхнего уровня убивает дочерний процесс. `Llm__MaxOutputTokens` больше не используется: CLI не предоставляет в `codex exec` эквивалент прежнего параметра API. После ответа действует лимит JSON 256 КБ и проверки содержимого M2.

## Протокол и границы

Каждый вызов создаёт временный каталог, записывает туда JSON-схему, передаёт prompt через stdin (`-`), затем запускает `codex exec --json --ephemeral --skip-git-repo-check --sandbox read-only --ignore-user-config -C <temp> --output-schema <schema> --output-last-message <answer> -`. `--model` добавляется только при заданном `Llm__Model`. Каталог удаляется после успеха и ошибки; процесс запускается без shell-интерпретации аргументов. Рабочий каталог не содержит checkout проекта. CLI наследует только переменные, нужные для поиска исполняемого файла, ChatGPT login, сертификатов и прокси; GitHub и другие ключи приложения не передаются. Временный каталог создаётся системным API с отдельным именем на каждый вызов.

Ответ читается из файла финального сообщения и должен быть непустым JSON-объектом. CLI ограничивает форму `--output-schema`; M2 дополнительно проверяет обязательные поля, ID требований, типы сценариев и разрешённые пути. В `LlmResponse` передаются `usage.input_tokens` и `usage.output_tokens` из события `turn.completed`, затем они суммируются и сохраняются в результат запуска. Денежная оценка не вычисляется: стоимость зависит от модели и плана ChatGPT и не равна простому пересчёту API-токенов.

Неуспешный exit code, отсутствие финального файла или `turn.completed`, неверный JSON и отсутствие токенов завершают вызов ошибкой. Отсутствующий исполняемый файл и истёкший timeout имеют отдельные сообщения. Для ошибок входа и лимита CLI возвращается краткая категория; сырой stderr, prompt, ответы и секреты не журналируются. Успешный вызов записывает только модель и числа токенов. Автоматического повтора нет: без достоверной информации о расходе первого процесса повтор может удвоить расход. Worker фиксирует причину блокировки запуска.

Тест `LlmClientTests` использует фальшивый исполняемый файл, проверяет аргументы, схему, stdin, JSONL и расход, а также ошибки и регистрацию DI. Реальный smoke-вызов отдельно подтвердил поддержку перечисленных флагов и формат `turn.completed` установленного CLI. [Приёмка М6](m6-evidence.md) подтвердила сквозной push→M2→M5 с настоящим `codex exec`.
