# Локальная приёмка М4

`tests/QaAgent.IntegrationTests/M4PublishingTests.cs` создаёт временный bare Git remote и два коммита продукта. Publisher получает checkout точного `headSha`, сгенерированный тест и локальный screenshot. Он создаёт ветку `qa/<short-sha>-<run-id>`, коммитит тест и `revision/commit_<short-sha>.md`, пушит ветку и возвращает сохранённые ссылки и manifest артефактов.

Проверки теста:

- Родитель QA-коммита равен исходному `headSha`.
- В ветке есть только сгенерированный тест и отчёт; намеренно изменённый рабочий файл продукта не опубликован.
- Отчёт содержит SHA, ID требования, расход LLM и ссылку на screenshot через локальную страницу результата.
- Подмена исходника теста после валидации блокирует публикацию, при этом локальный отчёт остаётся.
- Повтор на новом checkout того же запуска сверяет существующий QA-коммит и возвращает тот же SHA без новой записи.

`bash scripts/check.sh` проверяет формат, сборку, миграцию, архитектуру, все тесты и M1 сценарии. HTTP-страница, Basic аутентификация и выдача артефактов реализованы в `RunEndpoints`; live-проверка страницы на реальном результате worker требует LLM-провайдера. После его настройки следующий push должен подтвердить реальные `Publication.BranchUrl` и `Publication.ReportUrl` в GitHub и ссылки на доказательства в браузере; шаг записан в `TODO.md`.

После перезапуска локального LaunchAgent `/healthz` ответил `200`; запрос страницы без ключа получил `401` с `WWW-Authenticate: Basic`, а запрос с ключом к отсутствующему run ID получил `404`. Это подтверждает регистрацию маршрута и защиту, но не заменяет просмотр реального опубликованного результата.

Код М4 отправлен в GitHub коммитами `c40d9db` и `8084d5e`. После перезапуска сервиса [ручной повтор workflow](https://github.com/akkne/qa-tester-agent/actions/runs/39714416577) доставил диапазон `c40d9db..8084d5e` и создал запуск `baa1e67f-5363-415e-b6ef-07142ad229fb`. API вернул `Completed/Blocked` с точной причиной отсутствия `Llm:Model` и `Llm:BaseUrl`. Локальная HTML-страница этого запуска с HTTP Basic ответила `200` и показала статус и причину. QA-ветка для этого запуска не создавалась, так как анализ М2 не мог начаться.
