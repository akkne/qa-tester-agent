# Контракт локального API

Контракт М1 реализован для приёма и просмотра базового состояния запуска; расширенные поля результата появятся в М2–М4. API слушает loopback-интерфейс. Workflow runner обращается к нему с локального MacBook. Аутентификация отдельным ключом из `.env`, сравнение без логирования значения.

## Создать или найти запуск

`POST /api/runs`

```json
{
  "repository": "owner/repo",
  "branch": "main",
  "baseSha": "40-символьный SHA",
  "headSha": "40-символьный SHA",
  "profileId": "demo"
}
```

Сервер сверяет разрешённый репозиторий/ветку с конфигурацией, формат SHA и ненулевой первый `baseSha`. Worker проверяет существование обоих коммитов. Ответ `202 Accepted` содержит `runId`, `state`, `resultUrl` и признак `duplicate`; повторное событие возвращает тот же запуск. Ошибка входа — `400`, неразрешённый репозиторий — `403`, недоступные SHA/окружение дают последующий `BLOCKED` с причиной. Workflow не выводит ключ и тело с секретами в лог.

## Просмотр

| Метод и путь | Ответ |
| --- | --- |
| `GET /api/runs/{runId}` | SHA, этапы, итоговый статус, находки, тесты, покрытие, длительность, использование LLM, ссылка на QA-ветку и отчёт |
| `GET /runs/{runId}` | Простая HTML-страница того же результата |
| `GET /api/runs/{runId}/artifacts/{artifactId}` | Разрешённый screenshot или trace без прямой выдачи произвольного пути |
| `GET /healthz` | Готовность локального API и БД |

Артефакты выдаются только по ID из БД после нормализации пути внутри каталога запуска. HTML экранирует содержимое отчёта и логов.
