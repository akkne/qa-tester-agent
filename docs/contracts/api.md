# Контракт локального API

Контракт М1–М4 реализован для приёма и просмотра запуска. API слушает loopback-интерфейс. Workflow runner обращается к нему с локального MacBook. Аутентификация отдельным ключом из `.env`, сравнение без логирования значения.

## Создать или найти запуск

`POST /api/runs`

```json
{
  "repository": "owner/repo",
  "branch": "main",
  "baseSha": "40-символьный SHA",
  "headSha": "40-символьный SHA",
  "profileId": "demo",
  "rerun": false
}
```

Сервер сверяет разрешённый репозиторий/ветку с конфигурацией, формат SHA и ненулевой первый `baseSha`. Worker проверяет существование обоих коммитов. Ответ `202 Accepted` содержит `runId`, `attempt`, `state`, `resultUrl`, `pageUrl` и признак `duplicate`; повторное событие возвращает последнюю попытку, а после `BLOCKED` или при `rerun: true` — новую попытку. Ошибка входа — `400`, неразрешённый репозиторий — `403`, недоступные SHA/окружение дают последующий `BLOCKED` с причиной. Workflow не выводит ключ и тело с секретами в лог.

## Просмотр

| Метод и путь | Ответ |
| --- | --- |
| `GET /api/runs/{runId}` | SHA, итоговый статус, анализ, тесты, покрытие, использование LLM, публикация с QA-веткой и отчётом; заголовок `X-Agent-Key` |
| `GET /api/runs/{runId}/report` | Markdown-отчёт запуска после публикации; заголовок `X-Agent-Key` |
| `GET /runs/{runId}` | Простая HTML-страница результата; HTTP Basic с ключом API в поле пароля |
| `GET /runs/{runId}/activity?after=N` | Новые записи живой ленты запуска, состояние и следующий номер записи; тот же HTTP Basic |
| `GET /runs/{runId}/artifacts/{artifactId}` | Screenshot, trace, лог, покрытие или локальный отчёт по сохранённому ID; тот же HTTP Basic |
| `GET /healthz` | Готовность локального API и БД |

Артефакты выдаются только по ID из сохранённого в БД списка после нормализации пути внутри каталога запуска и проверки ссылок файловой системы. HTML экранирует содержимое анализа и путей.
