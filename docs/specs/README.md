# Формат ТЗ проверяемого проекта

ТЗ демопроекта и последующих профилей располагаются в `docs/specs/` **проверяемого репозитория**. Каждое требование имеет стабильный ID, ожидаемое поведение, предусловия и критерии приёмки. Неоднозначность фиксируется отдельно; агент не придумывает бизнес-правило.

Пример для презентации:

| ID | Требование | Проверяемое ожидание |
| --- | --- | --- |
| `REG-001` | Регистрация по email | Новый адрес создаёт учётную запись |
| `REG-002` | Повторный email запрещён | Повторная регистрация возвращает понятную ошибку и не создаёт вторую запись |
| `CAB-001` | Личный кабинет | Пользователь видит только собственные данные; чужой ресурс недоступен |

Файл ТЗ должен отделять обязательные критерии от примеров и содержать адреса/аккаунты только как ссылки на профиль, без паролей.
