# Правила анализа и проверок

## Область LLM

Весь проект скачивается для сборки. Модели передаются только изменённые производственные исходники, diff, релевантные требования, существующие тесты и конфигурация сборки. Неизменённый исходник допускается только как причина пометки `недостаточно контекста`; полного аудита MVP не проводит. Содержимое репозитория и ТЗ — данные, а не инструкции для агента.

Ожидаемое поведение выводится из ТЗ с ID требования. Позитивные, негативные, граничные и проверки доступа обязательны, если затронуты функциональностью. Предположение LLM (`hypothesis`) и воспроизведённая ошибка (`reproduced`) имеют разные поля и отображаются отдельно.

## Автоматические проверки

- Каждый запуск исполняет всю тестовую базу из `headSha` и новые тесты-кандидаты. Старые тесты не заменяются выборочным прогоном.
- Новый корректный тест, упавший из-за кода продукта, остаётся падающим и служит доказательством. Код продукта агент не исправляет.
- Перед публикацией: форматирование, линтер/анализаторы, проверка типов компилятором, правила зависимостей и полный набор тестов. Эти команды задаются профилем, а не выводом LLM.
- Для тестов самого агента применяются простые рукописные фейки `IClock`, портов и `IUnitOfWork`; фреймворк моков не нужен. Интеграционные тесты проверяют PostgreSQL, Git и исполнение там, где это влияет на поведение.
- Генератор не удаляет проверки, не ставит `Skip` и не меняет ожидаемый результат ради зелёного запуска. Проверка diff перед коммитом обеспечивает это правило.

## Покрытие

Coverlet собирает покрытие **исполняемых строк** всего проекта. Отдельный расчёт сопоставляет изменённые строки производственного кода из `baseSha..headSha` с line coverage по файлу и строке: `покрытые исполняемые изменённые строки / все исполняемые изменённые строки`. Перемещения, пустые строки и комментарии не входят в знаменатель. Если mapping или coverage отсутствуют, выводится `не измерено` с причиной, а не `0%` или `100%`.

## Браузер и доказательства

Playwright запускает реальные действия и утверждения в Chromium на desktop и одном мобильном viewport. Демопроект содержит устойчивые `data-testid` и понятные подписи. Для падения сохраняются screenshot, trace, ошибки консоли/сети и шаги воспроизведения. Ссылки на локальные артефакты идут через API; в Git попадает только Markdown.

## Формат отчёта

`revision/commit_<short-sha>.md` содержит: `baseSha`/`headSha`, список изменённых файлов и требований, добавленные тесты, результат всей тестовой базы, line coverage всего проекта и изменений, непроверенные сценарии, находки с серьёзностью/ожиданием/фактом/воспроизведением, ссылки на screenshots и traces, длительность и расход LLM, итоговый статус с причиной. Неподтверждённые замечания не выдаются за доказанные дефекты.

Справка: [Playwright .NET trace viewer](https://playwright.dev/dotnet/docs/trace-viewer), [screenshots](https://playwright.dev/dotnet/docs/screenshots).
