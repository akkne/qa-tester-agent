# Приёмка М5: два последовательных обновления

Команда `bash scripts/check_m5_cycle.sh` создаёт временный Git remote и два push в `main`. Она не меняет продукт в рабочем репозитории. Первый push вносит контролируемый дефект доступа к чужому кабинету (`DEMO-REG-05`); во время М3 в checkout этого SHA добавляется тест-кандидат. QA-ветка содержит только этот тест и отчёт. Затем тест принимается в исходную ветку, проверяется его падение до исправления, вносится исправление и отправляется второй push. Повторить презентацию можно командой `python3 scripts/record_m5_presentation.py /tmp/qa-agent-m5-cycle-evidence` после прогона.

| --- | --- | --- |
| Исходный код | `a6db7e5eda3cf1fc1d9b0310a4b511da03717ffa` | База для первого push |
| Первый push с дефектом | `29f13998e82d31dcfdeb49b425bb89d5b0d68061` | 3 из 52 тестов упали; desktop и mobile Chromium получили 200 вместо 403, сохранены screenshots и traces |

| Принятие теста | `f4686126c8ee1862871036cac008d56d3823fac9` | Новый тест в исходной ветке отдельно упал на дефектном продукте |
| Второй push с исправлением | `f2bbf7e2d99c9a34f00b06818d9772aee4d30e27` | Все 52 теста и desktop/mobile Chromium прошли; M3 вернул `Passed` |

Локальные доказательства находятся в игнорируемом Git каталоге `artifacts/m5-acceptance/`: `summary.json`, логи обоих прогонов, лог принятого теста до исправления, screenshots, traces и [40-секундная запись презентации](../artifacts/m5-acceptance/m5-presentation.mp4). Видео показывает итог проверок на отдельных слайдах без звукового сопровождения.

`bash scripts/check.sh` дополнительно проверяет дубликаты, параллельную доставку и рестарт с сохранением того же `runId`, запрет ветки `qa/**`, фильтрацию обновлений только отчёта и недоступный SHA. Повторная публикация одной QA-ветки проверяется `M4PublishingTests`. Во время приёмки М5 HTTP-адаптер LLM повторял временные сетевые ошибки до трёх попыток. После перехода на `codex exec` этот адаптер удалён; актуальные проверки приведены в [описании CLI](codex-exec.md).

Это локальная приёмка на контролируемом дефекте. Сквозной live-проход worker с настоящим LLM, реальной GitHub QA-веткой и страницей результата остаётся в `TODO.md` после смены адаптера.

Код М5 отправлен в GitHub коммитами `a6db7e5` и `2d6a366`. [Workflow доставки](https://github.com/akkne/qa-tester-agent/actions/runs/39715655097) успешно передал диапазон `c14bf63..2d6a366` локальному API и создал запуск `61cb3065-e896-4c12-897b-2f1d11dde690`. API зафиксировал точный полный диапазон и завершил запуск `Blocked` до анализа с причиной: `M2 analysis requires Llm:Model, Llm:BaseUrl and an available LLM service.` На момент запуска использовался прежний HTTP-адаптер, а значения `Llm__Model` и `Llm__BaseUrl` были пусты.

После коммита с индикатором М5 сервис перезапускался во время следующего push. Первый [workflow](https://github.com/akkne/qa-tester-agent/actions/runs/39715902403) получил `connection refused`; его повтор успешно создал запуск `c70c1bcb-8020-4297-b9b4-5ba018951b7b` для `2d6a366..cde5998`. Он также завершился `Blocked` только из-за LLM. Workflow теперь повторяет отказ соединения с ограничением времени.
