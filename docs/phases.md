# Фазы реализации

Фазы описывают проверяемые результаты. Оценка в часах из [плана демонстрации](delivery.md) остаётся ориентиром, а не заменяет критерии готовности. М0 завершена коммитом `51a2a6c`; М1 прошла локальную и GitHub-приёмку. М2 реализована и прошла offline-проверку с фейковым LLM; для live-проверки нужен настроенный провайдер. М3 прошла локальную приёмку на исправном и намеренно сломанном SHA. М4 реализована и прошла локальную публикацию в bare Git remote; live-публикация зависит от настроенного LLM. Следующий этап разработки — **М5**.

## Граница текущей работы

М0 создаёт компилируемые проекты, доменные правила и интерфейсы. Он не утверждает, что интеграции GitHub, PostgreSQL, LLM или Docker уже работают. `POST /api/runs`, worker и проверяемая регистрация входят в М1 и следующие фазы; их нельзя считать готовыми по наличию шаблонных классов.

М1 завершена: API, миграция PostgreSQL, очередь, worker, точный Git diff, Docker и workflow проверены на синтетическом репозитории, включая несколько коммитов, повтор события, перезапуск и два хоста. Настоящий push `94228c3..e5341e2` доставлен через self-hosted runner: [GitHub Actions run 39673152222](https://github.com/akkne/qa-tester-agent/actions/runs/39673152222) создал один запуск с точным диапазоном. [Повтор диапазона](https://github.com/akkne/qa-tester-agent/actions/runs/39708957282) вернул тот же `runId`; [повтор первой загрузки с нулевым `before`](https://github.com/akkne/qa-tester-agent/actions/runs/39669137103) использовал явный первый base SHA.

В М2 worker при настроенном LLM сохраняет план, гипотезы и исходники тестов в БД. Фейковый LLM на реальном checkout сгенерировал позитивный, негативный и access-control тесты: они собрались и исполнились. Два исправления доступны только при ошибках сборки; существующие тесты и продукт не переписываются. Без `Llm:Model` worker завершает запуск `BLOCKED` с причиной.

В М3 worker после М2 запускает форматирование, полную сборку и все тесты в Docker с Coverlet; поднимает приложение из того же `headSha`, проверяет SHA через `/healthz` и исполняет desktop/mobile Chromium. Результат и пути к локальным артефактам сохраняются в БД. При недоступном стенде, браузере или покрытии статус `BLOCKED`; воспроизведённые падения дают `FAILED`. [Локальная приёмка М3](m3-evidence.md) включает исправный прогон и отдельный коммит с удалённой проверкой владельца кабинета, который провалил тесты и оба браузерных сценария с screenshots/traces. Live-проверка единого worker-прохода пока зависит от настройки LLM, как указано в `TODO.md`.

В М4 worker сохраняет Markdown-отчёт локально, коммитит только сгенерированные тесты и `revision/commit_<short-sha>.md` в `qa/<short-sha>-<run-id>`, пушит ветку и сохраняет ссылки в БД. Повтор публикации сверяет существующий коммит с исходным SHA и тестами. `GET /runs/{id}` показывает итог, расход LLM, тесты и доказательства; артефакты выдаются по сохранённому ID после HTTP Basic аутентификации ключом API. [Локальная приёмка М4](m4-evidence.md) проверяет ветку, отчёт, отсутствие продуктовых правок и повтор публикации. Реальная GitHub-публикация ждёт live LLM-прохода.
