# Фазы реализации

Фазы описывают проверяемые результаты. М0–М5 прошли локальную приёмку. М1 прошла GitHub-приёмку. М6 завершила [сквозную live-приёмку](m6-evidence.md) М2–М5 с новым `codex exec`: два push продукта, принятые тесты, исправление дефекта, Docker/Chromium и QA-публикация на GitHub.

Автоматический запуск** | Демопроект с ТЗ и стартовыми тестами; Docker; GitHub Actions на self-hosted runner; API приёма push; PostgreSQL/EF Core; очередь и один worker; Git CLI с точным диапазоном SHA | Push создаёт ровно один запуск на `baseSha..headSha`; повтор события идемпотентен; `qa/**` и только отчёты не запускают работу; первый base SHA задан явно |

## Граница текущей работы

М0 создаёт компилируемые проекты, доменные правила и интерфейсы. Он не утверждает, что интеграции GitHub, PostgreSQL, LLM или Docker уже работают. `POST /api/runs`, worker и проверяемая регистрация входят в М1 и следующие фазы; их нельзя считать готовыми по наличию шаблонных классов.

М1 завершена: API, миграция PostgreSQL, очередь, worker, точный Git diff, Docker и workflow проверены на синтетическом репозитории, включая несколько коммитов, повтор события, перезапуск и два хоста. Настоящий push `94228c3..e5341e2` доставлен через self-hosted runner: [GitHub Actions run 39673152222](https://github.com/akkne/qa-tester-agent/actions/runs/39673152222) создал один запуск с точным диапазоном. [Повтор диапазона](https://github.com/akkne/qa-tester-agent/actions/runs/39708957282) вернул тот же `runId`; [повтор первой загрузки с нулевым `before`](https://github.com/akkne/qa-tester-agent/actions/runs/39669137103) использовал явный первый base SHA.

В М2 worker через авторизованный `codex exec` сохраняет план, гипотезы и исходники тестов в БД. Live-проход М6 сгенерировал позитивный, негативный и access-control тесты, которые собрались и воспроизвели дефект продукта. Два исправления доступны только при ошибках сборки; существующие тесты и продукт не переписываются. Неустановленный CLI, отсутствие входа и лимит времени завершают запуск с причиной.

В М3 worker после М2 запускает форматирование, полную сборку и все тесты в Docker с Coverlet; поднимает приложение из того же `headSha`, проверяет SHA через `/healthz` и исполняет desktop/mobile Chromium. Результат и пути к локальным артефактам сохраняются в БД. При недоступном стенде, браузере или покрытии статус `BLOCKED`; воспроизведённые падения дают `FAILED`. [Локальная приёмка М3](m3-evidence.md) включает падение браузерных сценариев с screenshots/traces; [live-приёмка М6](m6-evidence.md) подтвердила полный worker-проход.

В М4 worker сохраняет Markdown-отчёт локально, коммитит только сгенерированные тесты и `revision/commit_<short-sha>.md` в `qa/<short-sha>-<run-id>`, пушит ветку и сохраняет ссылки в БД. Повтор публикации сверяет существующий коммит с исходным SHA и тестами. `GET /runs/{id}` показывает итог, расход LLM, тесты и доказательства; артефакты выдаются по сохранённому ID после HTTP Basic аутентификации ключом API. [Локальная приёмка М4](m4-evidence.md) и [реальная GitHub-публикация М6](m6-evidence.md) проверены.

В М5 локальный Git-сценарий выполняет первый push с дефектом `DEMO-REG-05`, воспроизводит его новым тестом-кандидатом и двумя браузерными сценариями, публикует тест в QA-ветку, принимает его в `main`, подтверждает падение до исправления и выполняет второй push с исправлением. Полная база на втором SHA проходит. Повторы временных сбоев LLM ограничены; дубликаты и запрет циклов QA-ветки остаются проверками М1/М4. Результаты и запись приведены в [приёмке М5](m5-evidence.md).

В М6 настоящий GitHub push с новым требованием `DEMO-REG-07` прошёл M2–M4 через `codex exec`: сгенерированные тесты воспроизвели ошибку, QA-ветка и отчёт опубликованы. После принятия тестов и исправления продукта полный диапазон завершился `Passed`: 84 теста, desktop/mobile Chromium, 22/23 покрытых изменённых исполняемых строк и идемпотентный повтор. Дополнительный браузерный сценарий воспроизвёл дефект на старом SHA со screenshots/traces и прошёл на исправленном SHA. Встреченные ошибки сканера секретов, проверки ID требований и расчёта покрытия исправлены. Подробности в [приёмке М6](m6-evidence.md).
