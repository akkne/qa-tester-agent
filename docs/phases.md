# Фазы реализации

Фазы описывают проверяемые результаты. Оценка в часах из [плана демонстрации](delivery.md) остаётся ориентиром, а не заменяет критерии готовности. М0 завершена коммитом `51a2a6c`; текущий шаг — **М1**.

| Фаза | Содержание | Критерий завершения |
| --- | --- | --- |
| **М0. Основа** | Документация и контракты; все C# проекты и solution; направления зависимостей; доменные состояния и порты; composition root; конфигурация окружений; шаблон демопроекта; базовые unit-тесты и локальные проверки | Solution восстанавливается, форматируется, собирается, тестируется одной командой; реальные секреты исключены из Git; перечень будущих адаптеров и граница М1 понятны |
| **М1. Автоматический запуск** | Демопроект с ТЗ и стартовыми тестами; Docker; GitHub Actions на self-hosted runner; API приёма push; PostgreSQL/EF Core; очередь и один worker; Git CLI с точным диапазоном SHA | Push создаёт ровно один запуск на `baseSha..headSha`; повтор события идемпотентен; `qa/**` и только отчёты не запускают работу; первый base SHA задан явно |
| **М2. Анализ и тесты** | Контекст из ТЗ/diff, LLM через `ILlmClient`, JSON-схемы, план проверок, анализ логики и безопасности, генерация тестов с двумя исправлениями ошибок генерации | Новое требование получает исполняемые позитивные, негативные и access-control тесты; гипотезы отделены от воспроизведённых проблем |
| **М3. Исполнение и браузер** | Полная сборка и тестовая база, Coverlet по исполняемым и изменённым строкам, стенд из того же SHA, Chromium desktop/mobile, screenshots/traces | Ошибка демофичи воспроизводится тестом и через Playwright; недоступный стенд не даёт `PASSED` |
| **М4. Публикация** | Markdown `revision/commit_<short-sha>.md`, QA-ветка только с тестами/отчётом, push, простая страница результата и локальные артефакты | Результат доступен в GitHub и браузере, включая доказательства и расход LLM |
| **М5. Стабилизация демо** | Два последовательных обновления, принятие тестов, исправление продукта, проверки дубликатов/циклов/сбоев LLM, запись презентации | Второй push выполняет прежние принятые тесты и подтверждает исправление; повторное событие не дублирует работу |

После М5 отдельно планируются GitLab, несколько проектов и стеков, облачный запуск, GitHub App, PR-комментарии, трекер, полный аудит, исследовательский браузер и управление библиотекой тестов. При нехватке времени сокращается оформление UI; автоматический запуск, исполняемые тесты и доказательства остаются обязательными.

## Граница текущей работы

М0 создаёт компилируемые проекты, доменные правила и интерфейсы. Он не утверждает, что интеграции GitHub, PostgreSQL, LLM или Docker уже работают. `POST /api/runs`, worker и проверяемая регистрация входят в М1 и следующие фазы; их нельзя считать готовыми по наличию шаблонных классов.

М1 внедряет API, PostgreSQL-очередь, worker и точный Git diff. Пока М2 и М3 не реализованы, обработанный запуск получает `BLOCKED` с явной причиной после сохранения диапазона. Для завершения М1 нужен действующий приватный GitHub remote и self-hosted runner: локальная интеграционная проверка не заменяет доставку реального push.
